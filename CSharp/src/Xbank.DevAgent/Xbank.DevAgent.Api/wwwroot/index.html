            Agent models
            
          

          
Planner, Developer, Reviewer, and the final Release Manager are required. Planner creates the implementation contract, Developer executes it, and Reviewer independently confirms the changes. Jira and security are optional and start disabled.

          

        


        

          Workflow retry
          
          
          
          
After a workflow error, start again from a fresh clone and agent conversation, with the previous error as context. Retries are additional attempts after the first run and share its AI call and USD budget. Cancellation, input requests, validation rejections, unavailable build prerequisites, and configured limits stop the run.

        


        

          Build verification
          
          
Build the solution after applying changes and show the result. Build failures are reported without starting another repair cycle.

        


        

          Agentic turn limits
          
          Normal — 1×
          
          
          
Simple · 0.5×Normal · 1×Hard · 3×

          
Scale total AI calls, USD budget, conversation messages, and every agent's model turns. Normal keeps the current limits; Simple halves them (60 turns becomes 30), and Hard triples them. You can adjust individual limits afterward.

          
Limits apply across all agents for this run. Further AI calls stop when either limit is reached. Budget uses reported tokens and configured model prices; a call in progress can exceed the budget, and unpriced usage cannot be counted.

            Model token prices Shared across all agents
            
Set rates once per provider and model, in USD per million tokens. Every agent using that model shares these prices, regardless of reasoning effort. Blank rates stay unpriced; AIFA is free.

          Autonomy and completion
          
          
Off by default for faster finalization. Release Manager relies on prior approvals and gives a brief final summary. Enable to inspect the final diff and validate release evidence again.

          
          
When unchecked, Jira only gathers task input. Planner and later agents validate requirements. Applies when the Jira agent is enabled.

          
          
100% — Fully autonomous

          
          
          
GuidedAssistedCollaborativeHighly autonomousFully autonomous

          
Decide, implement, review, and repair without waiting for your answers. Record assumptions and finish with the patch or your selected completion actions.

          
At 100%, agents decide and record assumptions without waiting for your answers. Build policy, independent review, budgets, and Stop run still apply. Missing prerequisites can prevent completion.

          
          
          
          
These selections authorize completion actions when the run passes review. At 100% with no completion actions selected, the run finishes with the patch available for inspection.

        


        

          Instruction
          
          
          
Include expected behavior, constraints, and tests. For a manual request, include PROJECT-12345 or task number 12345. A Jira key creates user/PROJECT-12345; a bare task number creates user/TASK-12345. The agent edits only an isolated clone.

          
          
When enabled and an index is available, supported agents receive one compact graph prefetch for C# changes.

        


        

          Reference documents (optional)
          
Attach supporting material for this run. Plain text search works without external services. Optionally enable semantic search with Qdrant and embeddings. Documents are available to agents through search and removed after the run. Supported: text, Markdown, CSV, JSON, XML, YAML, HTML, source files, PDF with text, and DOCX.
